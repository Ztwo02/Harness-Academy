# 产品需求与页面设计

## 核心学习任务

目标用户是能读基本代码、想独立理解和实现 Agent Harness 的开发者。他遇到的问题常常很具体，例如“工具返回结果后，谁决定下一步？”平台应让他沿着一条真实源码链条回答这个问题，并在上游变更后仍能找回当时读过的代码。

一次有效学习的最小结果是：学习者能用自己的话解释一个场景，从章节打开证据，在对应版本指出函数和执行顺序，再完成一道要求核对源码的练习。优先保证这条路径可以离线重走。

| 用户任务 | 设计与交付阶段 | 可观察的验收结果 |
| --- | --- | --- |
| 从整体架构进入一章 | P1 学习中心显示四个项目、阶段、Pi 章节、前置关系和完成进度 | 初次打开能识别可学项目；从知识地图进入 Pi，后续项目显示计划阶段 |
| 导入并重现代码 | P1 GitHub 或本机 Git 目录导入，选择固定提交，浏览目录树 | 两种入口都能读到同一 Git 对象；重启、切换工作分支后章节行号仍一致 |
| 带着疑问读源码 | P1 Monaco 高亮、文件定位、证据区间和课程反向索引；P2 定义/引用导航 | 点证据定位首行并标出闭区间，从源文件返回引用该段的章节；符号命中不足时展示候选及定位依据 |
| 获得中文讲解 | P1 课程中的证据讲解；P2 源码导师按所选符号或问题展示已审稿的职责、调用链、数据流与场景 | 每条源码结论能回到本项目的固定行区间；材料不足时显示待验证问题。初期使用本地内容 |
| 看见运行过程 | P2 独立的 Mock LLM 和 Mock Tool 实验 | 可单步、暂停、继续、重置，按同一输入复现事件次序、状态前后差异及工具结果 |
| 留下学习痕迹 | P1 章节状态、笔记、疑问、单选练习及错题；P2 阶段复习与成果统计 | 重启后可继续，错题回链到原版本；复习时能比较首次和最近作答 |
| 学会跨项目比较 | P3–P5 分项目建课；P6 按架构维度对照并独立实现 | 每个比较单元有独立来源；资料不足的格子可明确留空 |

## 页面与操作

桌面布局使用左侧项目与章节导航，中间主阅读区，右侧证据与学习记录。窄窗口将侧栏收起为可用键盘打开的抽屉。项目名、课程版次和提交短 SHA 在课程与阅读器持续可见，详情可以复制完整 SHA。行标、证据类型、作答结果同时有文字提示。

| 页面 / 入口 | 主要内容与动作 | 空态或异常后的动作 |
| --- | --- | --- |
| 学习中心 `/` | 四张项目入口、继续学习、已完成/总章节；项目页按前置关系展示知识地图和可读章节 | 新用户进入 Pi 导入指引；计划中的项目显示开放阶段 |
| 仓库管理 `/repositories` | 选择 GitHub URL 或本机目录、固定提交、查看导入结果与版本 | 离线时可选本地目录；对象缺失给出仓库、SHA 与重试入口；空仓库提示需要已有提交 |
| 章节 `/releases/:release/lessons/:lesson` | 架构图、场景、十二项内容、源码与练习；记录疑问、更新学习状态 | 证据缺失时显示原因及修复入口；未验证的课程不能发布 |
| 阅读器 `/releases/:release/source` | 目录树、路径、行号、选区和本章/其他章节反链；用路径及行区间恢复深链 | 文件过大、二进制或编码不支持时显示文件元数据；路径不存在时返回版本目录 |
| 学习记录 `/review` | 按项目、版次和章节查笔记、未解疑问、错题；P2 显示复习队列与统计 | 无错题时引导回章节练习；更新课程后可切回旧版记录 |
| 源码导师与实验 `/lab`（P2） | 从章节带入知识点；选讲解或 Mock 场景，联动事件、状态与对应源码 | 明示模拟步骤和源码事实的区别；未映射的事件标为教学模拟 |
| 架构对比 `/compare`（P6） | 行为架构维度，列为项目版本，点单元格进入证据或原章 | 证据不足标“公开资料未覆盖”，保留差异和未决问题 |

## 首版端到端验收

1. 从空数据目录启动，在学习中心看到四个来源和仅开放的 Pi 入口。
2. 从已导入的 Pi 固定提交打开第一章架构导读，再打开至少一处真实函数。核对完整提交、路径、函数名、起止行和返回课程的链接。
3. 写一条笔记，登记一个疑问，先答错再答对，手动标记章节完成。关闭服务再启动，核对原文、状态、两次答题与完成比例。
4. 断网并移动上游分支，重复阅读上述章节。用本机仓库走第二条导入路径，同一提交下两条路径产生相同证据；修改工作区文件不会改变展示。
5. 用损坏的课程包和缺失的提交重试导入。错误消息能指出具体问题，上一版课程及学习记录仍可打开。

运行环境是单用户本地 Web 服务。源码、索引、笔记和答题数据保存在本机。P0 的评审对象是上述交互、数据与验证契约，应用端到端用例从 P1 实施。
