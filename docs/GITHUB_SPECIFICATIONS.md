# GitHub 协作与提交

项目远端为 [Ztwo02/Harness-Academy](https://github.com/Ztwo02/Harness-Academy)。main 保存可复核的基线；首次设计交付沿用远端已有历史。后续阶段从最新 main 按任务创建短期分支，例如 `codex/p1-source-reader`。每次推送前核对 origin、当前分支、差异与远端进度；遇到并行更改先取回并整合。

## 提交粒度

提交标题使用 `type(scope): 摘要`。type 可为 docs、feat、fix、test、refactor、chore；scope 取 phase0、sources、courses、reader、learning 等实际范围。每次提交解决一个可单独说明、可验证的问题。

- `docs(phase0): 定义固定版本的课程与证据契约`
- `feat(reader): 按课程提交定位源码区间`
- `fix(learning): 保留旧版课程的作答记录`

提交正文说明动机、关键取舍、验证命令与结果。涉及课程时列出项目、仓库、完整 SHA、课程版次及受影响证据；数据库变更给出迁移与恢复方式。只暂存本次任务相关文件，检查暂存区，保留原始需求与许可证。

## 评审与发布

1. PR 描述明确阶段、对应任务和用户可观察的结果，附复现步骤、测试及待验证项。涉及页面时附实际学习路径，涉及课程时附一条可以点击复核的源码引用。
2. 评审核对文档、Schema、DDL、读写行为和权限边界；抽查一个成功用例和一个失败用例。P0 使用 `python checks/phase0.py`；P1 起增加当期应用测试与端到端验收。
3. 后续阶段在评审通过后合并到 main。阶段交付记录提交 SHA、验收范围及负责人结论。GitHub 上已推送和负责人已验收是两个独立状态。
4. 保留可回溯历史，修复已共享提交时追加修订。上游基线升级、软件改动和用户学习数据分别管理；个人数据库、导入源码、令牌和本机路径不进入提交。
